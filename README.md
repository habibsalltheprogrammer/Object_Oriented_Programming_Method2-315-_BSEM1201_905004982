## Project Description

A simple REST API built with **Python FastAPI** for managing the Limkokwing University Library.
The system allows staff and students to search for books, borrow and return them,
track overdue loans, and handle multiple users at the same time using asynchronous programming.

---

## Features

- Search books by title, author, or category
- Borrow and return books
- Track overdue books and calculate fines (Le 1,000 per day)
- Support multiple users accessing the system at the same time (async/await)
- Interactive API documentation (auto-generated by FastAPI)

---

## API Endpoints (Part A)

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/books` | Get all books in the library |
| GET | `/books/search` | Search by title, author, or category |
| POST | `/borrow` | Borrow a book |
| POST | `/return` | Return a borrowed book |
| GET | `/overdue` | View all overdue books and fines |
| GET | `/users/{user_id}/books` | View books borrowed by a specific user |

## Part C – Reflection

**How APIs improve efficiency in Limkokwing library services:**

APIs allow different parts of a system to communicate with each other without needing to know
how the other part works internally. For the Limkokwing library, using an API means that the
library management system can be accessed from any device — a computer, phone, or tablet —
without changing the core system. Staff can search for books, process loans, and track fines from
a simple interface, while the API handles all the logic behind the scenes. This reduces manual
paperwork, saves time, and minimises human errors. Multiple staff members can also use the
system at the same time without conflict, thanks to asynchronous programming.

**SDG Alignment – SDG 4: Quality Education**

This project aligns with SDG Goal 4 (Quality Education) because it improves access to library
resources for students and staff at Limkokwing University. By digitising the library system, more
students can quickly find and borrow the books they need for their studies, supporting a better
learning environment.

**Challenges faced:**

The main challenge was handling multiple users trying to borrow the same book at the same time.
Without a lock mechanism, two users could both see a book as available and borrow it simultaneously,
causing data corruption. I solved this using Python's `asyncio.Lock()`. Another challenge was
structuring the JSON responses consistently so every endpoint returned data in the same format.

**Suggested improvement:**

If the library expanded its services, I would add a user registration and login system with JWT
token authentication, so only verified students and staff could access the API. This would make
the system more secure, especially if it were made publicly accessible online.
